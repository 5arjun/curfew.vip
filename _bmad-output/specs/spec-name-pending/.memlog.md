- (capability) CAP-1 (Phase 1) Background set detection & auto-sync (FR-1, FR-4): agent auto-discovers Serato data dir incl. USB/removable, detects completed sessions with no DJ action, idempotent+offline-queued sync. success: a completed real gig session appears on the dashboard next morning with no DJ action; re-run never duplicates; offline sets sync on reconnect.
- (capability) CAP-2 (Phase 1) Track-level enrichment via library join (FR-2): resolve BPM/key/genre from Serato library DB (V2 + master.sqlite), fall back to embedded tags for off-library, then visible 'Unknown'. success: in-library tracks show DB metadata; off-library show tag metadata; no source => 'Unknown', never guessed/omitted.
- (capability) CAP-3 (Phase 1) Agent tray presence (FR-5): menu-bar/tray icon + one settings panel (Serato path override only). success: icon reflects idle/syncing/failed/drive-not-connected; settings exposes only path override; no other agent UI surface.
- (capability) CAP-4 (Phase 1) Session classification-confidence signal (FR-27): compute a live/practice confidence signal from Phase 1 onward; confirmation-prompt behavior dormant until Phase 2 gate has something to protect. success: signal computed and stored per session in Phase 1; no confirmation prompt fires while every session is dashboard-only.
- (capability) CAP-5 (Phase 1) Personal dashboard per-set summary + energy arc + genre normalization (FR-6, FR-7, FR-8): per-set most-played, genre breakdown, BPM distribution, Camelot mixing stats, length, track count; BPM-vs-time energy arc; raw genres normalized via fixed table. success: any synced set renders its summary + energy arc; fragmented genre strings collapse to normalized buckets before display.
- (capability) CAP-6 (Phase 1) Style Evolution trend view (FR-9, FR-10): BPM range, genre diversity, key-usage month-over-month; library-to-setlist correlation trend. success: a DJ with >=1 month of synced sets sees month-over-month trend lines incl. whether recently-added tracks are reaching sets.
- (capability) CAP-7 (Phase 1) Library Utilization (FR-11, FR-12, FR-13): conversion rate over rolling window, aging shelf (unplayed 3+ months), time-to-first-play. success: DJ sees % of library ever played, a sortable aging-shelf list, and add-to-first-play elapsed time — all derived, no manual input.
- (capability) CAP-8 (Phase 1) Set Segments (FR-14, FR-15, FR-28): DJ marks labeled time-range segments (manual), system suggests boundaries from density/BPM/transition-smoothness (DJ confirms/adjusts), per-set stats sliceable by segment. success: a multi-context session yields suggested boundaries a DJ can confirm/edit; per-set stats filter by segment; a session may yield zero, one, or several dancefloor segments.
- (capability) CAP-9 (Phase 1) Layer 2 Enrichment (FR-16, FR-17, FR-18): optional venue/crowd/event-type/notes added post-hoc from web; unlocks richer comparisons; opt-in (off by default) location-based venue suggestion, confirm-or-edit never silent auto-fill. success: core dashboard works with zero enrichment; when added, enables club-vs-radio-style comparisons; location suggestion appears only after explicit opt-in and is never auto-saved.
- (capability) CAP-10 (Phase 1) Account & multi-provider auth (FR-29): sign up/log in via email+password, Google, Apple, or passkey; all link to one account by verified email; phone number required on file. success: mixing methods with the same verified email lands in one account (no duplicate); OAuth signups are prompted for phone before account is usable.
- (capability) CAP-11 (Phase 2) Social feed — follow, feed, profile, comments (FR-19, FR-20, FR-21, FR-26): DJs follow each other; feed renders sets as energy-arc thumbnails; profiles show recent sets + chosen aggregate stats; comments on a set respect its visibility tier. success: a followed DJ's new set appears in the follower's feed as an energy-arc thumbnail; comments are readable by anyone who can see the set.
- (capability) CAP-12 (Phase 2) Per-track hide & visibility tiers (FR-22, FR-23): per-track hide renders as a redacted placeholder (never omitted); each set is public / friends-only / private; default-on-sync public but only for sets synced after the DJ joins the social layer. success: a hidden track shows as a visible redaction with no track-count leak; a private one-toggle set never reaches feed/profile; Phase 1 sets are never retroactively exposed when Phase 2 policies ship.
- (capability) CAP-13 (Phase 2) Community comparisons — network + circle (FR-24, FR-25): descriptive (never 'winner') aggregate comparisons network-wide and scoped to a DJ's circle, built from aggregate stats never raw tracklists. success: a DJ sees the same comparison metric both network-wide and scoped to who they follow, framed descriptively, computed by cloud SQL over shared sets only.
- (capability) CAP-14 (Phase 1) Format-drift resilience (FR-1 NFR, §5.4): golden-file CI tests + agent-side error reporting tagged agent_version + signed auto-updater, with backfill from retained local raw data after a fix. success: a Serato format change is caught by CI or in-the-wild error reports, a signed update ships the fix, and affected sets are backfilled without duplication or overlay loss.
- (assumption) CAP-14 promoted format-drift resilience to a first-class capability (it was a cross-cutting NFR in the PRD but is load-bearing enough — golden-file tests, agent_version error reporting, signed updater, backfill — to be its own capability governed by AD-13). Flagged as an inference, not a PRD restructure.
- (constraint) Raw Serato .session files and raw library DB never leave the DJ's machine; only derived/normalized JSON syncs over HTTPS. Agent FS access capability-scoped to the configured Serato path only. (FR-3, AD-2, §5.2)
- (constraint) Edge computes, cloud stores: the edge owns all derivation from raw Serato data; the cloud never parses Serato binary or re-derives base metadata (may run SQL over already-synced clean rows). No paid AI/ML anywhere — all stats are arithmetic over parsed metadata, marginal per-DJ cost ~0. (AD-1, §5.3)
- (constraint) Per-DJ isolation enforced at the DB layer via null-safe RLS (auth.uid() IS NOT NULL AND auth.uid() = dj_id), never application-layer filtering. All cloud mutation goes through Supabase/PostgREST+RLS; agent's only write is the idempotent set sync. (AD-7, AD-8)
- (constraint) Sync is idempotent PUT on a deterministic set_id = hash(dj_id, session_identity) — namespaced by dj_id (shared-USB DJs can't collide), never a fresh UUID (would duplicate on backfill). Session is the immutable anchor; set boundaries once synced are stable in the cloud. (AD-4, AD-16)
- (constraint) Set content flows agent->cloud only; user overlays (Layer 2 enrichment, segments, per-track hide, visibility tier) are web-authored, cloud-only, never written back to the agent; the agent upsert is column-scoped to content and never touches an overlay column. No bidirectional sync. (AD-6, AD-16)
- (constraint) Phase 1 -> Phase 2 is additive, never a rewrite: Phase 2 adds fields, RLS read-policies, and Realtime subscriptions; it never restructures existing tables or the sync contract. Enforced by additive-only Supabase-CLI migrations in the monorepo. Sync contract evolution is additive-only; cloud accepts the last N agent_versions. (AD-15, AD-3)
- (constraint) Missing metadata renders as a visible 'Unknown' carrying the in_library flag — never guessed, never silently omitted. The 'Unknown' rate must stay honestly visible, not suppressed. (AD-11, SM-C1)
- (constraint) Reflection framing stays descriptive/comparative to the DJ's own baseline ('compared to what?'), never coach-graded; no streak counters, gamified-habit visuals, or celebratory milestone animations; copy favors community over status/flex (no 'best'/'winner'/ranking language). (§6.2, SM-C2, EXPERIENCE voice)
- (constraint) Serato only (no Rekordbox v1). Local agent is Tauri 2/Rust, macOS + Windows desktop; DJ-facing experience is a responsive website (desktop/laptop-first), no native mobile app. (§6.3, AD-11)
- (constraint) US-only at launch: CCPA-level posture sufficient at v1; GDPR-equivalent review deferred until international expansion. Formal CCPA-compliance review remains a pre-launch checklist item. (arch OQ#6)
- (constraint) Monetization is a single subscription tier, $6/month — a locked PM decision made deliberately against the WTP survey's one-time-payment preference; pricing surfaces show one plan with nothing to compare. (§7)
- (constraint) WCAG 2.2 AA floor across the website; every chart ships a text-equivalent (chart-summary) so the core value moment is reachable without seeing the chart; keyboard path for any drag interaction. (EXPERIENCE Accessibility Floor)
