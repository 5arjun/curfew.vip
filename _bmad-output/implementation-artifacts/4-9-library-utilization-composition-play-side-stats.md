# Story 4.9: Library Utilization composition + play-side utilization stats

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a DJ,
I want Library Utilization to show whether I keep replaying the same tracks, which tracks I actually lean on, and which I played once and forgot,
so that the page tells me how I'm *using* what I own instead of showing me a single conversion number.

## Non-negotiables

Everything below is derived and argued later in this file. If context is lost, these ten lines are the contract.

1. `web/` only. No `agent/`, no `shared/`, no schema migration. One additive **local-dev-only** `supabase/seed.sql` is the single exception (**D-23**).
2. Low-confidence predicate = **`listModel.ts`'s `isLowConfidenceSet`** (`confidence.value < 1.0 || track_count < HERO_MIN_TRACKS`), **not** `styleEvolution.ts`'s bare `< 1.0` (**D-20** — the bare one does not exclude soundchecks; see GAP-2).
3. Track identity = normalized **`title` + `artist`**, never `track_id` (**D-18**). Do not reuse `playsByTrack` (**GAP-4**).
4. Repeat-track rate formula is fixed in **D-17**. Trailing window `REPEAT_WINDOW_SETS = 5` **predecessors**, excluding the measured set.
5. Similarity matrix capped at `SIMILARITY_MATRIX_SETS = 10` (**D-19**), cap stated in the UI, degrading to a ranked list at phone widths (**D-22**).
6. Rotation size is **fixed at trailing 60 days**, renders **outside** the `aria-label="Conversion"` landmark, states its own window (**D-21**).
7. Every module: `<section className="lu-module dz-shell">` + `dz-dots`, **every branch inside the shell**, own insufficient-history copy, accessible name that never states a figure the visible UI declined to state.
8. `no-hardcoded-colors.test.ts` bans hex, `rgba(`, `hsl(`, `oklch/lab/color-mix(`, **and the words `transparent`/`currentColor`** across all of `web/app/**`. Heatmap intensity rides `opacity` or discrete `tokens.css` steps.
9. No ranking vocabulary anywhere ("top", "best", "#1", medals, badges) — `DESIGN.md:199`.
10. Test at the pure-function layer **plus** `renderToStaticMarkup` prop-threading assertions (**D-24**). No RTL, no jsdom. Then a real-browser DOM measurement at 1440/375/320.

### Five gaps found during story creation, not by `epics.md`

Story 4.7's Task 3 is the precedent: a gap named at story-creation time and resolved deliberately, rather than discovered mid-implementation and settled by whichever wiring was fastest to write.

**GAP-1 — AC-10 is a retrofit, not a wiring task; nothing on this page excludes low-confidence sets today.** `web/lib/sets/libraryConversion.ts` (990 lines) never reads `derived.confidence` — grep it. Story 4.3's meter, Story 4.2/4.7's trend, and Story 4.5's time-to-first-play all count soundcheck plays right now. AC-10 says "**this page** applies the same exclude-visibly contract Style Evolution does." Ruled in **D-20**.

**GAP-2 — there are THREE low-confidence predicates in this codebase, they disagree, and the obvious one is the wrong one.**
- `styleEvolution.ts:196` — module-private `isLowConfidence(set) = set.derived.confidence.value < 1.0` (Story 4.1's D-4: binary, no tier).
- `listModel.ts:86-89` — exported `isLowConfidenceSet(set) = confidence.value < 1.0 || trackCount < HERO_MIN_TRACKS` (`HERO_MIN_TRACKS === MIN_PLAYS_FOR_DETECTION === 6`, `dancefloor.ts:21`). Used by the dashboard's set list and most-played.
- `SetHeader.tsx:23` — a third, display-only `c.value <= 0.5 || c.track_count < 4`.

The trap: `agent/src-tauri/src/confidence.rs` is **symmetric by design** — its own doc comment says *"A session that's obviously 'not a set' (too few plays) and a session that's obviously a real set (long, naturally punctuated) both score `1.0`"*. `MIN_PLAYS_FOR_AMBIGUITY = 4`, and `LOW_CONFIDENCE_VALUE = 0.2` is only ever assigned to the dense-continuous ambiguous case. **So a 2–3 track soundcheck scores 1.0 and sails straight through `confidence.value < 1.0`** — the predicate AC-10's "same as Style Evolution" wording points at is precisely the one that does *not* do what AC-10 asks for. Ruled in **D-20**.

**GAP-3 — AC-7's rotation-size window is ambiguous as written, and the answer decides where the module renders.** "a trailing **60-day** window — matching Story 4.3's shipped conversion-rate default (60/30/14-day selectable scale)… so every window on this page stays consistent" reads either as *fixed at 60* or as *follows the shared dropdown*. Not cosmetic: `page.tsx:156-177` and `TimeToFirstPlay.tsx:33-39` establish a structural rule for this page — **window-governed modules render inside `LibraryUtilizationView`; window-independent modules render outside as siblings** — precisely so a control never appears to own a figure it cannot move. Ruled in **D-21**.

**GAP-4 — `playsByTrack` looks reusable and is not.** `page.tsx:74` builds one shared index and its comment warns that it used to be two and that the split caused a real bug — which invites reuse here. But `libraryConversion.ts:178-193` returns `Map<track_id, number[]>`: it `continue`s past any play missing `track_id` **and** any play with an unparseable `started_at`, and it carries **no set identity at all**. It therefore cannot answer AC-2, AC-4, AC-5 or AC-6, and its key space directly contradicts **D-18**. The one-shared-index rule is scoped to `playsByTrack`'s three conversion consumers. This story builds a **separate** set-membership index, and that is not a regression of the rule.

**GAP-5 — AC-11's real-browser pass is currently unperformable, and no prior story had this problem.** Story 4.6 retired the committed fixtures from the production read path (`web/lib/sets/index.ts:28-45`, explicit), production holds 0 sets / 0 plays (measured during Story 4.5's review), and there is **no seed file**: `supabase/config.toml:66-75` has `[db.seed] enabled = false` with `sql_paths = ["./seed.sql"]` pointing at a file that is not committed — and its own comment warns that enabling it while the file is missing breaks the migration-apply CI gate. ### Rulings — decided here so the dev agent does not have to settle them

AC-3 requires the repeat-track quantity to be "named as precisely as Story 4.1's amended AC-5 names 2^H — never left as 'a rate' for the implementation to settle," citing 4.1's D-10 lesson (a spec that described something other than what shipped). An agent asked to *rule* under time pressure picks whatever is fastest to write, which reproduces exactly that failure. So all of it is fixed here.

- **D-17 — Repeat-track rate.** For each surviving set that has at least one surviving predecessor: `(distinct tracks in that set that also appear in the up-to-5 surviving sets immediately preceding it) ÷ (distinct tracks in that set)`. The 5 are **predecessors only** — the measured set is not one of them. The surfaced figure is the **unweighted mean** of those per-set shares, with the **count of sets it averaged over stated alongside it**. The oldest surviving set has no predecessor and is excluded from the mean, never counted as 0% (D-8: a gap, never a fabricated zero). Unweighted is deliberate: the question AC-2 poses is "does a typical *night* repeat," so each night counts once regardless of length — and the small-set skew that would otherwise make this dangerous is exactly what D-20's predicate removes, which is why these two rulings must be implemented together or not at all. With exactly 2 surviving sets there is exactly 1 measurable set, which is why AC-2's gate is "≥2 captured sets."

  > **⚑ OPEN — Arjun's ruling owed before dev starts.** A second create-story pass ran on this story concurrently (see the reconciliation entry at the top of `sprint-status.yaml`) and ruled the *rejected alternative* instead: **a single ratio** — "of the distinct tracks across your trailing 5 surviving sets, the share appearing in more than one" — rejecting the mean on Story 4.5's skew lesson. The two passes agreed on everything else. The trade: the single ratio is simpler and cannot skew, but reads only the most recent block and so cannot answer "does a *typical* night repeat," which is the question AC-2 poses; D-17 answers that and is protected from the small-set skew the alternative fears by the compound predicate **both** passes adopted in D-20. **D-17 as written above is what to build absent a ruling otherwise**; the alternative is a contained swap inside the builder plus its tests, not a re-architecture. Do not implement both and do not average them.
- **D-18 — Track identity for all five play-side metrics is normalized `title` + `artist`, NOT `track_id`.** (a) These metrics never join to `library_track_events`, which is the only thing `track_id` exists to make joinable (`shared/src/index.ts:128-144`); (b) `track_id` is `?: string | null` — optional post-freeze, `null` whenever the source carried no portable path — so keying on it would silently drop off-library tracks from a "what do I lean on" list; (c) mixing the two key spaces double-counts one track whose plays split between rows that do and don't carry a hash. This matches `rightColumn.ts:115`'s existing `JSON.stringify([title, artist ?? ""])` key exactly. **Do not "fix" this into agreeing with `libraryConversion.ts`'s `track_id` keying** — that file answers a different question. Plays with a `null` title are excluded and their count disclosed (AD-11's "never omitted, never guessed"; `rightColumn.ts:114`'s own `title != null` guard).
- **D-19 — The similarity matrix is capped at the 10 most recent surviving sets**, reusing `MOST_PLAYED_RECENT_SETS = 10` (`rightColumn.ts:83`) rather than inventing a second "recent" scale on the same product. Export it as a named constant, and **state the cap in the UI** whenever more surviving sets exist than the matrix shows — a silent top-10 truncation reads as "this is all your history."
- **D-20 — The page's low-confidence contract.** (i) It applies **page-wide** — the meter, the trend, time-to-first-play, and all five new modules read the same surviving-set population under one page-level reveal. AC-10 says "this page"; and a single visible "N sessions hidden — show them?" control sitting above modules it does not govern is the same "one control appearing to own a figure it does not move" failure `page.tsx:156-177` already rules against, made worse by the control actively misdescribing its own scope. (ii) The predicate is **`listModel.ts`'s `isLowConfidenceSet`**, not Style Evolution's — per GAP-2, the bare `< 1.0` form does not exclude the short soundchecks AC-10 exists to keep out of a repeat rate, and `rightColumn.ts:60-64` records the shipped bug (a 1-play soundcheck deciding most-played) that the compound form was added to fix. AC-10 requires the *exclude-visibly contract*; the affordance is what is shared, and the divergence in predicate is deliberate and must be written into a comment at all three definition sites. (iii) **Consequence that must not be missed: the reveal's copy currently says "N low-confidence sessions hidden," which under the compound predicate would misdescribe what it hid.** Either widen the copy (e.g. "N short or low-confidence sessions") or pass a copy override — do not ship a count whose noun is wrong.
- **D-21 — Rotation size is fixed at a trailing 60 days**, renders **outside** `LibraryUtilizationView` as a sibling of it, and **states its own 60-day window in its own copy**. This is AC-7's literal text ("across a trailing 60-day window"); following the dropdown would leave the tile violating its own AC at the 14-day selection. It also keeps the module a server component, and — decisively — `LibraryUtilizationView.tsx:39` renders `<section className="lu-conversion" aria-label="Conversion">`, so nesting a play-side stat there would announce it to assistive tech inside a landmark named "Conversion". Same placement rule as `TimeToFirstPlay`, applied in the same direction.
- **D-22 — The similarity view degrades to a ranked "most alike" list below the width at which its cells can each meet 24×24**, reusing the workhorses row markup. A 10×10 grid cannot meet 24×24 at 320px inside `.lu`'s gutters; expect the degraded form to be the phone experience rather than an edge case. This is Story 4.8 AC-11's pattern for the Camelot wheel, which is the same problem already solved once.
- **D-23 — Author `supabase/seed.sql` (local-dev only) and enable `[db.seed]`.** Generated from the retained `recent-sets.fixture.json` sample data, it is additive, is never applied to production, and closes GAP-5 for this story and every story after it. Two cautions, both from `config.toml`'s own comment: the file **must be committed** in the same change that flips `enabled = true`, or the migration-apply CI gate breaks; and confirm the additive-only migration guard (`supabase/scripts/check-additive-only-migrations.sh`) does not treat a seed as a migration. **Do not re-point `web/lib/sets/index.ts` at the fixtures** — that silently reverts Story 4.6 and is the failure this ruling exists to prevent.
- **D-24 — Adopt a `renderToStaticMarkup` assertion harness for prop-threading.** `deferred-work.md` carries this as an open recommendation with a proven prototype (7 assertions incl. a negative control, built during the 4.5 merge, deleted rather than committed because adopting `web/`'s first component-render test "deserves its own decision"). This story is that decision, and it is the story that most needs it: it threads optional disclosure/model props through several new hops, and `?: string | null` at every hop means `tsc` and `eslint` stay green while a line silently stops rendering. `react-dom` is already a dependency — no new packages. Scope it narrowly: string assertions over rendered markup, **no RTL, no jsdom**, and every new threaded prop gets a negative control that removes it and asserts the copy disappears.

## Acceptance Criteria

Reproduced verbatim from `epics.md` Story 4.9 (lines 948-958):

1. **Given** the page today (Story 4.3's meter, plus Story 4.7 AC-3's incoming conversion trend), **When** Library Utilization renders, **Then** it has a real composition — the conversion pair reading as one unit sharing a single window selection, with the utilization stats below — rather than components stacked in arrival order. *(UX-DR17)*
2. **Given** ≥2 captured sets, **Then** a **repeat-track rate** renders: how many tracks recur across nearby sets, as the "am I playing the same thing every night" counterpart to the aging shelf's neglect signal. *(Epic-4 header note, 2026-08-07; Decision B — cold-start-honest by construction, since it needs no play Curfew never saw)*
3. **Given** repeat-track rate needs a definition that cannot drift, **Then** "nearby" means a **trailing 5-set window** (ruled 2026-08-07, party mode: wide enough to be forgiving of gaps between gigs without reading as counting ancient repeats) and the surfaced quantity is named as precisely as Story 4.1's amended AC-5 names 2^H — never left as "a rate" for the implementation to settle. *(4.1's D-10 lesson: a spec that described something other than what shipped)*
4. **Given** the same overlap data, **Then** a **set-similarity** view renders it as a matrix/heatmap across recent sets — an aggregate, non-time-series display that reads off a small history, unlike the trend lines. *(Cold-start density, per Story 4.7's rationale)*
5. **Given** play history, **Then** a **workhorses** list ranks tracks by **number of sets they appeared in**, not by play count — deliberately a different question from the dashboard's most-played, and the story file must state that difference so the two surfaces are never "fixed" into agreeing. *(Distinct from Story 3.6's `rightColumn` most-played)*
6. **Given** play history, **Then** a **one-and-done** list surfaces tracks played exactly once — the actionable mirror of AC-5. *(FR-12's neglect theme, play-side)*
7. **Given** play history, **Then** a **rotation size** tile shows distinct tracks against total plays across a **trailing 60-day window** — matching Story 4.3's shipped conversion-rate default (60/30/14-day selectable scale, no 90-day option — corrected 2026-08-07 after Story 4.3's own review caught the mismatch against an earlier draft of this AC) so every window on this page stays consistent — rendering as e.g. "340 plays, 180 unique." *(New)*
8. **Given** every stat here counts only Curfew-captured plays, **Then** the page says so once, plainly, in the product's own voice — framed as the DJ's record rather than as a limitation, and **never** as elapsed subscription time. *(Decision B's binding copy rule — no "since you joined," no "in your N months")*
9. **Given** a DJ with 0 or 1 sets, **Then** each component renders its own positive-framed insufficient state (repeat rate and similarity genuinely need ≥2 sets) rather than the page blanking wholesale. *(UX-DR19; Story 4.7 AC-8's precedent)*
10. **Given** low-confidence sets, **Then** this page applies the same exclude-**visibly** contract Style Evolution does — soundchecks must not silently inflate a repeat rate. *(FR-27; Story 4.1 AC-2)*
11. **Given** 375px and 320px, **Then** the composition holds with no horizontal overflow and every target meets WCAG 2.2 AA SC 2.5.8's 24×24 minimum, **measured against the DOM in a real browser**. *(4.1's review lesson; UX-DR21, UX-DR22)*

- **The two highest-risk items are Task 2 and Task 3, not the metrics.** The metrics are arithmetic over an array. Task 2 decides the input population for *eight* modules, three already shipped — get it wrong and every figure is subtly wrong *together*, which is the hardest defect class to see, because nothing disagrees with anything.
