## What Went Well (keep doing)

1. **Story 3.6's Camelot key-parsing fix.** Reading `key_value` INT instead of the free-text `key` field took harmonic-mixing coverage from ~12% to ~94%. This was a headline dashboard stat that would have been wrong for the vast majority of sets if it had shipped as originally written — caught in review, not in prod.
2. **The three-layer adversarial review (Blind Hunter / Edge Case Hunter / Acceptance Auditor) kept its track record.** Real, independently-converged catches every story: AC-15 contrast failures in 3.6, phone-gate cookie scoping and password-reset-without-inbox-proof gaps in 3.10, the TempoSpark sparse-data dishonesty bug in 3.8. Twice in 3.6's review, two layers independently flagged something that turned out to be a false positive on direct file inspection — the process self-corrected before reaching Arjun.
3. **Decision-needed items resolved fast, in-session, with no rework.** Every story's review surfaced 1-5 decision points; all were ruled on directly by Arjun in the same session rather than blocking or deferring.
4. **Authoritative pre-story design specs are working as intended.** `3-6-dashboard-home.md`, `3-7-set-detail.md`, `3-8-energy-arc.md`, `3-10-settings.md` — written before dev/story creation — held up as ground truth through review with zero contradictions found. This is a different (and effective) fix for a different problem than the doc-staleness issues below.

## Challenges (systemic, no blame)

1. **Dev Notes / File List self-report staleness recurred — again.** The Epic 2 retro created ai-11 specifically because this pattern hit Story 2.3b three times. It recurred three more times in Epic 3: 3.6's Dev Agent Record claimed FloatingNav.tsx was "untouched WIP" when it had been substantially rewritten; 3.8's Task 8.2 claimed a keyboard-nav pass that hadn't actually happened; 3.10's own epics.md design-session callout was stale in the same commit that introduced it. Two epics of "this is a known pattern" hasn't been enough to stop it — it needs a literal checklist step, not a norm.
2. **Large-surface-area stories cost extra review structure.** Story 3.6 needed three separate review chunks (agent/logic, UI components, CSS/config — ~6.6k reviewable lines); Story 3.7 needed a frontend/backend split. Not a quality problem, but a review-planning cost that should be budgeted up front on big stories rather than discovered mid-review.
3. **Concurrent-session collisions continue.** 3.6 chunk 2a and 3.10's review shared an uncommitted working tree; 3.4's review caught a concurrent 3.10 commit that swept in an unrelated deferred-work.md edit. A third instance surfaced live during this very retro (see below).
4. **A carried-forward action item's trigger fired and nobody checked it landed — again.** ai-6 (Decision A propagation to PRD/Architecture Spine) was pinned to "Epic 3 story-creation" and never actually happened until this retro caught it — the identical failure shape as ai-2 in the Epic 1→2 retro. `epics.md` Overview did carry the decision (written during design-epics authoring), but PRD §1 Vision/§3 Glossary and the Architecture Spine had zero trace of it through all of Epic 3.
5. **New this session — the `AR-#` architecture-requirements register is a ghost.** 16 distinct `AR-#` tags are cited across every epic's acceptance criteria (including several in Epic 3); none resolve to a definition anywhere in the current PRD, addendum, or Architecture Spine. Not new drift — the 2026-07-21 implementation-readiness report (before Epic 1 started) already flagged `AR-2` as "owed to Architecture Spine," and it sat unfixed for the entire project so far. By contrast, all 20 `AD-#` (architecture *decision*) tags used in epics.md resolve cleanly — the decision register is trustworthy, the requirements register isn't.

## Key Takeaways

1. **A pinned trigger on a carried-forward action item is not self-enforcing** — this is now confirmed twice (ai-2 in Epic 1→2, ai-6 in Epic 2→3). The fix that's actually worked both times is catching it at the *next* retrospective, not the story-creation step it was pinned to.
2. **Self-report staleness (Dev Notes/File List) is a distinct failure mode from spec-before-code ambiguity** — Arjun's authoritative-design-doc practice solves the latter well; the former needs its own checklist-level fix (ai-14).
3. **Foundational cross-reference integrity can decay invisibly for a long time** — the `AR-#` gap sat unflagged for the entire project because nothing forced anyone to resolve the citation until this retro went looking.
4. **The three-layer adversarial review is still the single highest-leverage practice in this project** — real bugs, independently converged on, epic after epic, including one process-level self-correction this epic (the two false-positive findings caught before triage).
5. **Concurrent-session collisions are a recurring operational risk**, not a one-off — three instances now (3.6/3.10 shared tree, 3.4's stray commit, and this retro's live Epic 4 discovery).
