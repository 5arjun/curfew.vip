## What Went Well (keep doing)

1. **The 3-layer adversarial review keeps earning its cost.** On 2.8, 2.9a, 2.10, and 2.11, all three review layers (Blind Hunter, Edge Case Hunter, Acceptance Auditor) independently converged on the *same* headline bug each time — 2.10's tray status never updating after a live link event, 2.8's `ON CONFLICT` clause silently dropping `status`. Real functional bugs, not overlapping nits. Continues the pattern Epic 1's retro already named.
2. **Real credentials, real verification, no theater.** Every auth/signing story was walked end-to-end against real infrastructure: real Google+Apple OAuth linking to one account (2.3b), a real passkey register+sign-in against prod (2.4), a real USB reconnect cycle (2.6), a real throwaway DJ deleted via the Admin API with cascade confirmed by direct query (2.11).
3. **The agent-can't-reach-this boundary was handled honestly.** Vercel login, Apple Developer credential creation, real OAuth consent screens, physical USB reconnects — every one got explicitly flagged as needing Arjun directly, with the story left `in-progress` rather than falsely promoted to `review`.
4. **Genuine security catches from review, not planning.** 2.10's `Cargo.lock` regression (a stale `rustls` pair with a verified cross-scheme-redirect header-leak bug) and a CSRF nonce round-trip added to the deep-link handoff both surfaced during code review.

## Challenges (systemic, no blame)

1. **OAuth-consent-flow stories cost extra review rounds.** Story 2.3b needed three code review rounds — not because the code was weak, but because AC-1's real test (same email, Google then Apple, confirm one account) needed a human to drive two real OAuth consent flows and clean up prod state between attempts. Every other story landed in one or two rounds. **Pattern to budget for:** anything requiring a real third-party OAuth/payment consent screen costs a review round or two more than everything else — relevant again for Stripe Checkout in Epic 7.
2. **Story-file bookkeeping drift, recurring.** 2.3b's third review explicitly flagged "Dev Notes/File List staleness reconciled — third recurrence of this class in this file." Not a one-story problem — a recurring failure mode where the Dev Agent Record falls out of sync with what actually shipped.
3. **An action item assigned to the wrong story shape can silently die.** See the previous-retro follow-through below (ai-2) — assigning a fix's DoD to a story whose actual scope never touches the affected code is as good as leaving it unassigned.

## Significant Fixes Applied This Session

1. **`sync_payload_schema_path()` / ai-2 — closed.** Replaced the `env!("CARGO_MANIFEST_DIR")`-based runtime path resolution with `include_str!("../../../shared/schema/sync-payload.schema.json")` — the schema is now compiled directly into the binary, so a bundled/installed agent needs no `shared/` source tree on disk at all. Removed `SYNC_PAYLOAD_SCHEMA_RELPATH`, `sync_payload_schema_path()`, and the now-unreachable `SchemaLoadError::Read` variant. Full four-command cargo gate (240 unit + 9 integration tests) + workspace-wide pnpm lint/typecheck/build/test re-verified green. Story 3.2 (idempotent set sync) no longer inherits this bug.
2. **Tauri updater signing keypair generated.** `pnpm dlx @tauri-apps/cli@latest signer generate --ci -p "" -w ~/.tauri/curfew-agent-updater.key` — no password (simplest for CI: `TAURI_SIGNING_PRIVATE_KEY` alone is sufficient, no `_PASSWORD` secret). Public key wired into `agent/src-tauri/tauri.conf.json`'s `plugins.updater.pubkey`, replacing the placeholder. Private key stays local-only at `~/.tauri/curfew-agent-updater.key`, outside the repo.

Both changes are uncommitted in the working tree, left for Arjun to review and commit.

## Key Takeaways

1. **A carried-forward action item needs its assignment double-checked against the receiving story's actual scope** — "reclassified as a functional blocker" doesn't mean much if the story it's pinned to structurally can't touch the affected code.
2. **OAuth/payment-consent-flow stories are structurally slower to verify** — not a quality problem, a real-human-in-the-loop cost. Budget for it, especially heading into Epic 7's Stripe integration.
3. **The 3-layer adversarial review is still the single highest-leverage practice in this project** — real bugs, converged on independently, epic after epic.
4. **Closing a flagged gap same-session beats re-deferring it** — both ai-2 and the updater keypair were sitting on the ledger with no forward motion; a direct ruling in this retro closed both in minutes.
