## Deferred from: code review of 1-4-library-join-for-in-library-enrichment (2026-07-22)

- **Flag for Story 1.9 (golden-file suite) — volume-hosted `database V2` path resolution is unproven against real data.** The legacy join resolves a play by trying the absolute path, then stripping one leading `/` (Story 1.2 findings §5/D4). Confirmed correct for a root-hosted library; **never observed succeeding on a USB/volume-hosted one** — the spike's USB session resolved 0 of 116 plays for an unrelated reason (tracks were never in Serato's library), so the convention was never exercised end-to-end. If a volume-hosted catalogue stores paths relative to its own volume (`Theo Indian/track.wav` rather than `Volumes/ARJUN SSD/Theo Indian/track.wav`), those tracks silently read as off-library. Deliberately not "fixed" — a third strip-the-library-root step would be guessing at a schema, which AD-11 forbids. Resolution: read one USB `database V2`'s stored path strings during 1.9's fixture work, then confirm or extend with a real fixture behind it. [agent/src-tauri/src/joiner/legacy.rs — `LegacyLibrary::get`]
- **Flag for Story 1.9 — path *encoding* mismatch is untested in either direction, and Open Question #6 does not cover it.** The catalogue is keyed by `HashMap<PathBuf, _>`, i.e. byte-exact equality, while APFS is case-insensitive and macOS stores filenames decomposed (NFD). If `.session` and `database V2` disagree on Unicode normalization or case for the same file, every accented artist in the library (`Café`, `Beyoncé`, `Björk`, `Sigur Rós` — a large share of a real dance library) silently reads as off-library, which is indistinguishable from the app working correctly. **No evidence either way; do not add a normalization layer speculatively.** Same inspection, same file, same ten minutes as the entry above: while a real `database V2` is open for 1.9, compare its stored path bytes against the `.session` bytes for one accented track. [agent/src-tauri/src/joiner/legacy.rs — `LegacyLibrary::get`, `tracks: HashMap<PathBuf, LibraryTrack>`]
- **Spine deviation — Serato 4+ `in_library` is guessed, against the Consistency Conventions' "never guessed".** `joiner::serato4::join_session` sets `in_library: true` unconditionally for every `history_entry` row. No column in the explored schema distinguishes "played from an indexed library track" from "played straight off disk", and unlike the legacy path there is no lookup that could miss, so there is no honest way to compute it today. Defensible on the merits and documented at the function, but it contradicts an explicit spine rule (ARCHITECTURE-SPINE.md Consistency Conventions: the `in_library` flag is "never omitted, never guessed") and that record belongs here, not only in an implementation-artifact story file. **Does not affect AC-4 routing** — a `NULL` column still reports `None` regardless of the flag — only the flag's own display semantics (the in-library/off-library glossary distinction, PRD §3). Confirm against a real `master.sqlite` during Story 1.3b, which will hold a live connection to the fuller schema; if no membership signal exists there either, the spine convention needs an explicit carve-out for this format rather than a silent one. [agent/src-tauri/src/joiner/serato4.rs — `join_session`]
- **Serato 4+ `join_session` may be redundant once Story 1.3b lands.** The play log and this story's metadata live on the **same `history_entry` row**. If 1.3b selects `bpm`/`key`/`genre` in its own play-log query, it never needs to correlate anything and this function becomes a second round-trip to rows it already holds. Not removed now (1.3b is backlog, and the function is tested and unwired), but 1.3b should delete rather than call it if the columns come along for free. [agent/src-tauri/src/joiner/serato4.rs — `join_session`]
- **`sane_bpm` has no upper bound.** Accepts any finite positive value, so a corrupted-but-positive BPM (e.g. a mis-decoded `"999999.00"`) passes through as a real measurement into what will become Story 1.7's tempo averages. Not required by any AC; the correct threshold is a product call (DJs do spin 200-300 BPM genres) better made once Story 1.7 actually consumes this value rather than picked arbitrarily now. [agent/src-tauri/src/joiner/mod.rs — `sane_bpm`]
- **Duplicate-path last-wins tiebreak is an unconfirmed assumption.** `LegacyLibrary::from_database_bytes` keeps the last-processed record when two carry the same path, on the belief that file order reflects the catalogue's own append order (so a re-analysed track's newer BPM wins). Unlike the volume-hosted-path and Unicode-encoding entries above, this assumption has no Story 1.2 findings citation behind it. Confirm against a real catalogue with a genuinely re-analysed duplicate during Story 1.9's fixture work, alongside the other two. [agent/src-tauri/src/joiner/legacy.rs — `duplicate_paths_resolve_to_the_last_record`]
- **`serato4::join_session` fails the whole session on one row's type-coercion error.** `row.get::<_, Option<f64>>` etc. propagate a column type-coercion failure as `Err` via `?`, so `.collect()` fails the *entire session's* join rather than degrading just that one field to `None` — asymmetric with the legacy path's per-field grace (a gap in one column there costs only that field). Low real-world likelihood (requires a non-conforming SQLite column type) and arguably consistent with this file's own precedent that schema-shape anomalies are hard errors (`missing_table_is_an_error_not_an_empty_set`) — worth revisiting with real `master.sqlite` data during Story 1.3b rather than patching speculatively now. [agent/src-tauri/src/joiner/serato4.rs — `join_session`]
